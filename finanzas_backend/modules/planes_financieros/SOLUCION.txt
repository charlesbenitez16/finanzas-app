GUÍA DE SOLUCIÓN — MÓDULO planes_financieros
================================================================================
Entidad PLAN_FINANCIERO / tabla `plan_financiero`. Reparto del ingreso
estilo 50/30/20 personalizable. Reglas clave:
  - los 3 porcentajes suman 100 (CHECK del schema)
  - un solo plan activo por usuario (uq_plan_activo_usuario, índice parcial)
  - vista_plan_vs_real: metas del plan vs. ejecución real de un mes.


--------------------------------------------------------------------------------
1. domain/entities.py  ->  PlanFinanciero
--------------------------------------------------------------------------------
    from decimal import Decimal, ROUND_HALF_UP

    def porcentajes_suman_100(self) -> bool:
        suma = (self.porcentaje_gasto_fijo + self.porcentaje_ahorro
                + self.porcentaje_gasto_libre)
        return suma == Decimal("100")

    def esta_activo(self) -> bool:
        return self.activo

    def esta_vigente(self, fecha) -> bool:
        if self.fecha_inicio and fecha < self.fecha_inicio:
            return False
        if self.fecha_fin and fecha > self.fecha_fin:
            return False
        return True

    def _meta(self, ingreso_total: Decimal, porcentaje: Decimal) -> Decimal:
        return (ingreso_total * porcentaje / Decimal("100")).quantize(
            Decimal("0.01"), rounding=ROUND_HALF_UP)

    def meta_gasto_fijo(self, ingreso_total: Decimal) -> Decimal:
        return self._meta(ingreso_total, self.porcentaje_gasto_fijo)

    def meta_ahorro(self, ingreso_total: Decimal) -> Decimal:
        return self._meta(ingreso_total, self.porcentaje_ahorro)

    def meta_gasto_libre(self, ingreso_total: Decimal) -> Decimal:
        return self._meta(ingreso_total, self.porcentaje_gasto_libre)

POR QUÉ:
- porcentajes_suman_100() SÍ va en la entidad, y este es el CONTRAEJEMPLO
  explícito de la lección de catalogos: NivelPrioridad no podía decidir
  sola si era "la más baja" porque necesitaba ver a sus hermanas. Acá los
  3 porcentajes son atributos DEL MISMO plan -> la entidad tiene todo lo
  que necesita para validar su invariante.
- GOTCHA de Decimal: si los porcentajes llegan como Decimal (del
  serializer o de la base), `50 + 20 + 30 == Decimal("100")` funciona. Si
  hubiera floats de por medio, usá `abs(suma - Decimal("100")) < Decimal("0.01")`.
- _meta() aplica ROUND(x, 2) como hace vista_plan_vs_real
  (`ROUND(b.total_ingresos * pf.porcentaje_gasto_fijo / 100, 2)`).
- esta_vigente(): misma forma que en servicios_fijos / ingresos.

3. infrastructure/repositories.py  ->  DjangoPlanFinancieroRepository
--------------------------------------------------------------------------------
    from typing import Optional

    def _a_entidad(self, m):
        return PlanFinanciero(
            id=m.id, usuario_id=m.usuario_id, nombre=m.nombre,
            porcentaje_gasto_fijo=m.porcentaje_gasto_fijo,
            porcentaje_ahorro=m.porcentaje_ahorro,
            porcentaje_gasto_libre=m.porcentaje_gasto_libre,
            fecha_inicio=m.fecha_inicio, fecha_fin=m.fecha_fin, activo=m.activo,
        )

    def obtener_por_id(self, plan_id):
        try:
            return self._a_entidad(PlanFinancieroModel.objects.get(id=plan_id))
        except PlanFinancieroModel.DoesNotExist:
            return None

    def crear(self, plan):
        m = PlanFinancieroModel.objects.create(
            usuario_id=plan.usuario_id, nombre=plan.nombre,
            porcentaje_gasto_fijo=plan.porcentaje_gasto_fijo,
            porcentaje_ahorro=plan.porcentaje_ahorro,
            porcentaje_gasto_libre=plan.porcentaje_gasto_libre,
            fecha_inicio=plan.fecha_inicio, fecha_fin=plan.fecha_fin,
            activo=plan.activo,
        )
        return self._a_entidad(m)

    def actualizar(self, plan):
        PlanFinancieroModel.objects.filter(id=plan.id).update(
            nombre=plan.nombre, porcentaje_gasto_fijo=plan.porcentaje_gasto_fijo,
            porcentaje_ahorro=plan.porcentaje_ahorro,
            porcentaje_gasto_libre=plan.porcentaje_gasto_libre,
            fecha_inicio=plan.fecha_inicio, fecha_fin=plan.fecha_fin,
            activo=plan.activo,
        )
        return plan

    def listar_por_usuario(self, usuario_id):
        qs = PlanFinancieroModel.objects.filter(usuario_id=usuario_id).order_by("-fecha_inicio")
        return [self._a_entidad(m) for m in qs]

    def obtener_plan_activo(self, usuario_id):
        m = PlanFinancieroModel.objects.filter(usuario_id=usuario_id, activo=True).first()
        return self._a_entidad(m) if m else None

4.2 activar_plan_financiero.py

    from django.db import transaction

    def ejecutar(self, plan_id):
        plan = self.repositorio.obtener_por_id(plan_id)
        if plan is None:
            raise PlanNoEncontrado(f"No existe el plan {plan_id}")
        with transaction.atomic():
            activo = self.repositorio.obtener_plan_activo(plan.usuario_id)
            if activo is not None and activo.id != plan.id:
                activo.activo = False
                self.repositorio.actualizar(activo)     # DESACTIVAR primero
            plan.activo = True
            return self.repositorio.actualizar(plan)    # ACTIVAR después

  POR QUÉ este orden: uq_plan_activo_usuario es
  `UNIQUE(usuario_id) WHERE activo = TRUE`. Si activás el nuevo antes de
  desactivar el viejo, hay un instante con 2 filas activas -> IntegrityError.
  transaction.atomic() asegura que un crash entre los 2 UPDATE no deje al
  usuario sin ningún plan activo. Importar django.db.transaction en
  application/ es un compromiso pragmático; la versión "pura" sería un
  puerto Unit-of-Work.

    class PlanesFinancierosView(APIView):
        def get(self, request):
            repo = DjangoPlanFinancieroRepository()
            planes = repo.listar_por_usuario(request.user.id)
            return Response(PlanFinancieroSerializer(planes, many=True).data)

        def post(self, request):
            e = PlanFinancieroSerializer(data=request.data); e.is_valid(raise_exception=True)
            caso = CrearPlanFinancieroUseCase(repositorio=DjangoPlanFinancieroRepository())
            try:
                plan = caso.ejecutar(
                    usuario_id=request.user.id,
                    porcentaje_gasto_fijo=e.validated_data["porcentaje_gasto_fijo"],
                    porcentaje_ahorro=e.validated_data["porcentaje_ahorro"],
                    porcentaje_gasto_libre=e.validated_data["porcentaje_gasto_libre"],
                    nombre=e.validated_data.get("nombre", "Mi plan"),
                    fecha_inicio=e.validated_data.get("fecha_inicio"),
                    fecha_fin=e.validated_data.get("fecha_fin"),
                )
            except PorcentajesNoSuman100 as ex:
                return Response({"detail": str(ex)}, status=status.HTTP_400_BAD_REQUEST)
            return Response(PlanFinancieroSerializer(plan).data, status=status.HTTP_201_CREATED)

    class ActivarPlanView(APIView):
        def post(self, request, plan_id):
            caso = ActivarPlanFinancieroUseCase(repositorio=DjangoPlanFinancieroRepository())
            try:
                plan = caso.ejecutar(plan_id)
            except PlanNoEncontrado as ex:
                return Response({"detail": str(ex)}, status=status.HTTP_404_NOT_FOUND)
            return Response(PlanFinancieroSerializer(plan).data)

    class ComparativaView(APIView):
