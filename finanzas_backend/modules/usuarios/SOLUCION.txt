3. application/use_cases/registrar_usuario.py

Cambio de firma: `hasher` pasa a ser un parámetro REQUERIDO (sin default).

    from dataclasses import dataclass
    from typing import Callable

    from modules.usuarios.domain.entities import Usuario
    from modules.usuarios.domain.exceptions import EmailYaRegistrado
    from modules.usuarios.domain.ports.repositories import UsuarioRepository


    @dataclass
    class RegistrarUsuarioUseCase:
        repositorio: UsuarioRepository
        hasher: Callable[[str], str]

        def ejecutar(self, nombre: str, email: str, password_plano: str) -> Usuario:
            email = email.strip().lower()
            if self.repositorio.existe_email(email):
                raise EmailYaRegistrado(f"Ya existe un usuario con el email {email}")
            usuario = Usuario(
                nombre=nombre.strip(),
                email=email,
                password_hash=self.hasher(password_plano),
                activo=True,
            )
            return self.repositorio.crear(usuario)

POR QUÉ:
- Normalizar el email (strip + lower) ANTES de comparar y de guardar: así
  "Ana@X.com " y "ana@x.com" son el mismo usuario, que es lo que el
  negocio espera. Guardás siempre la forma normalizada.
- existe_email() es una validación amable (mensaje claro). El guardia
  REAL contra duplicados es el UNIQUE de la base: si dos requests entran a
  la vez, uno va a fallar con IntegrityError. Opcional: capturarlo en el
  repositorio y re-lanzar EmailYaRegistrado (ver punto 4).
- El dominio NO conoce el algoritmo de hash. `hasher` se inyecta:
    * la vista le pasa django.contrib.auth.hashers.make_password
    * el test le pasa  lambda p: f"hash::{p}"
  Requerido (sin default) a propósito: si tuviera `= make_password` como
  default, este archivo importaría django.contrib.auth.hashers al cargar,
  y los tests de application/ deben poder correr SIN Django configurado
  (ver README de catalogos: "Python puro, sin Django").
- Usuario nace sin id -> es_nueva() == True -> el repo le asigna id.

    @dataclass
    class AutenticarUsuarioUseCase:
        repositorio: UsuarioRepository
        verificador: Callable[[str, str], bool]   # (password_plano, hash) -> bool

        def ejecutar(self, email: str, password_plano: str) -> Usuario:
            email = email.strip().lower()
            usuario = self.repositorio.obtener_por_email(email)
            if usuario is None or not usuario.esta_activo():
                raise CredencialesInvalidas("Email o contrasena incorrectos")

                raise CredencialesInvalidas("Email o contrasena incorrectos")
            return usuario

7. infrastructure/repositories.py  ->  DjangoUsuarioRepository
--------------------------------------------------------------------------------
    from typing import Optional

    from django.db import IntegrityError

    from modules.usuarios.domain.entities import Usuario
    from modules.usuarios.domain.exceptions import EmailYaRegistrado
    from modules.usuarios.domain.ports.repositories import UsuarioRepository
    from modules.usuarios.infrastructure.models import UsuarioModel


    class DjangoUsuarioRepository(UsuarioRepository):
        def _a_entidad(self, modelo: UsuarioModel) -> Usuario:
            return Usuario(
                id=modelo.id,
                nombre=modelo.nombre,
                email=modelo.email,
                password_hash=modelo.password_hash,
                fecha_registro=modelo.fecha_registro,
                activo=modelo.activo,
            )

        def obtener_por_id(self, usuario_id: int) -> Optional[Usuario]:
            try:
                return self._a_entidad(UsuarioModel.objects.get(id=usuario_id))
            except UsuarioModel.DoesNotExist:
                return None

        def obtener_por_email(self, email: str) -> Optional[Usuario]:
            modelo = UsuarioModel.objects.filter(email__iexact=email).first()
            return self._a_entidad(modelo) if modelo else None

        def existe_email(self, email: str) -> bool:
            return UsuarioModel.objects.filter(email__iexact=email).exists()

        def crear(self, usuario: Usuario) -> Usuario:
            try:
                modelo = UsuarioModel.objects.create(
                    nombre=usuario.nombre,
                    email=usuario.email,
                    password_hash=usuario.password_hash,
                    activo=usuario.activo,
                )
            except IntegrityError as exc:
                raise EmailYaRegistrado(usuario.email) from exc
            return self._a_entidad(modelo)

        def actualizar(self, usuario: Usuario) -> Usuario:
            UsuarioModel.objects.filter(id=usuario.id).update(
                nombre=usuario.nombre,
                email=usuario.email,
                password_hash=usuario.password_hash,
                activo=usuario.activo,
            )
            return usuario

POR QUÉ:
- _a_entidad() es la frontera ORM<->dominio. Todo lo demás la reusa.
- email__iexact -> Django genera un WHERE UPPER(email) = UPPER(%s) (o
  ILIKE): match case-insensitive, coherente con la normalización del
  caso de uso.
- .first() devuelve None en vez de tirar DoesNotExist: más limpio para
  "puede no haber".
- create() no pasa id (autoincremental) ni fecha_registro (DEFAULT NOW()
  en la tabla; auto_now_add en el modelo). Si necesitás la fecha en la
  entidad devuelta, hacé:
      modelo.refresh_from_db(); return self._a_entidad(modelo)
- Capturar IntegrityError en crear() cierra la carrera que existe_email()
  no puede: dos altas simultáneas del mismo email.
- actualizar() usa .update() (UPDATE parcial) en vez de get()+save():
  una sola query, sin releer. Devolvemos la misma entidad porque los
  campos los seteamos nosotros.

    from rest_framework.permissions import AllowAny
    from rest_framework.response import Response
    from rest_framework.views import APIView
    from django.contrib.auth.hashers import check_password, make_password

    from modules.usuarios.application.use_cases.autenticar_usuario import AutenticarUsuarioUseCase
    from modules.usuarios.application.use_cases.registrar_usuario import RegistrarUsuarioUseCase
    from modules.usuarios.domain.exceptions import CredencialesInvalidas, EmailYaRegistrado
    from modules.usuarios.infrastructure.repositories import DjangoUsuarioRepository
    from modules.usuarios.interfaces.api.serializers import (
        LoginSerializer, RegistroUsuarioSerializer, UsuarioSerializer,
    )


    class RegistroView(APIView):
        authentication_classes = []
        permission_classes = [AllowAny]

        def post(self, request):
            entrada = RegistroUsuarioSerializer(data=request.data)
            entrada.is_valid(raise_exception=True)
            caso = RegistrarUsuarioUseCase(
                repositorio=DjangoUsuarioRepository(), hasher=make_password,
            )
            try:
                usuario = caso.ejecutar(
                    nombre=entrada.validated_data["nombre"],
                    email=entrada.validated_data["email"],
                    password_plano=entrada.validated_data["password"],
                )
            except EmailYaRegistrado as e:
                return Response({"detail": str(e)}, status=status.HTTP_400_BAD_REQUEST)
            return Response(UsuarioSerializer(usuario).data, status=status.HTTP_201_CREATED)


    class LoginView(APIView):
        authentication_classes = []
        permission_classes = [AllowAny]

        def post(self, request):
            entrada = LoginSerializer(data=request.data)
            entrada.is_valid(raise_exception=True)
            caso = AutenticarUsuarioUseCase(
                repositorio=DjangoUsuarioRepository(), verificador=check_password,
            )
            try:
                usuario = caso.ejecutar(
                    email=entrada.validated_data["email"],
                    password_plano=entrada.validated_data["password"],
                )
            except CredencialesInvalidas as e:
                return Response({"detail": str(e)}, status=status.HTTP_401_UNAUTHORIZED)
            return Response(UsuarioSerializer(usuario).data)

POR QUÉ:
- La vista arma el caso de uso con los adaptadores concretos
  (DjangoUsuarioRepository + make_password/check_password). Es el ÚNICO
  lugar donde se juntan dominio + Django.
- El serializer valida FORMA (email válido, largo mínimo). El caso de uso
  valida NEGOCIO (email único, activo, hash). La excepción de dominio se
  traduce a código HTTP: EmailYaRegistrado->400, CredencialesInvalidas->401.
- AllowAny + authentication_classes=[] en estas dos: si no, no podrías
  registrarte sin estar ya logueado.
