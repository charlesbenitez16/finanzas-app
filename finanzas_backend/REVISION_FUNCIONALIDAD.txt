[N1] NUEVO — modules/ingresos/infrastructure/repositories.py :: crear()
     referencia una variable antes de que exista
--------------------------------------------------------------------------------
    def crear(self, ingreso: Ingreso) -> Ingreso:
        modelo = IngresoModel.objects.create(usuario_id=ingreso.usuario_id, monto=ingreso.monto,
                    periodo_mes=ingreso.periodo_mes, periodo_anio=ingreso.periodo_anio,
                    fuente=ingreso.fuente, descripcion=ingreso.descripcion,
                    fecha_registro=ingreso.fecha_registro,fecha=modelo.fecha)
                                                          # ^^^^^^^^^^^^^ ese `modelo` todavia no existe

Este arreglaba el bug original (F5: faltaba pasar `fecha`), pero el
valor que se pasa es `modelo.fecha` en vez de `ingreso.fecha`. El
problema es que `modelo` es justo la variable que esta misma línea está
creando (`modelo = IngresoModel.objects.create(...)`): Python evalúa
todo el lado derecho ANTES de asignarlo a `modelo`, así que en ese
momento `modelo` todavía no tiene ningún valor dentro de la función.
Como `modelo` sí se asigna en algún punto de la función, Python la trata
como variable local en toda la función, y usarla antes de esa asignación
tira:
    UnboundLocalError: local variable 'modelo' referenced before assignment

Efecto: POST /api/ingresos/ va a fallar SIEMPRE (peor que antes: ahora
ni siquiera llega a pegarle a la base, explota en Python puro apenas se
arma el create()).

FIX (una sola palabra):
    fecha_registro=ingreso.fecha_registro, fecha=ingreso.fecha
                                                  ^^^^^^^
(la lectura de `_a_entidad()`, unas líneas arriba en el mismo archivo,
ya quedó bien: usa `fecha=modelo.fecha` correctamente porque ahí
`modelo` SÍ es el parámetro recibido, no algo que se esté creando en esa
misma línea — no confundir ambos casos.)

Como el dataclass no tiene default para ese campo, esto lanza:

[F11] SIGUE ROTO (de otra forma) — GastosView.post() sigue sin ser un
      endpoint de "gasto puntual"
--------------------------------------------------------------------------------
    class GastosView(APIView):
        def post(self, request: Request) -> Response:
                e = GastoSerializer(data=request.data)
                e.is_valid(raise_exception=True)
                # deducir categoria/prioridad del servicio fijo:
                servicio = DjangoServicioFijoRepository().obtener_por_id(
                    e.validated_data["servicio_fijo_id"])
                ...

Ahora valida con `GastoSerializer` (antes usaba
`RegistrarPagoServicioFijoSerializer`, que era el bug original F11), pero
el cuerpo del método SIGUE siendo el flujo de "pago de servicio fijo"
(busca `servicio_fijo_id`, llama a
`RegistrarPagoDeServicioFijoUseCase`). El problema: en
`GastoSerializer`, el campo `servicio_fijo_id` está declarado
`read_only=True` (ver modules/gastos/interfaces/api/serializers.py,
línea 17-19) — un campo read_only NUNCA aparece en `validated_data`
cuando validás datos de ENTRADA. Entonces:
    e.validated_data["servicio_fijo_id"]
lanza `KeyError: 'servicio_fijo_id'` (antes del ajuste, con el
serializer viejo, esto SÍ funcionaba porque
RegistrarPagoServicioFijoSerializer no lo marca read_only).

Además, `RegistrarGastoUseCase` (el caso de uso para un gasto puntual,
sin servicio_fijo_id) sigue importado y sin usar en este archivo — no
existe ningún endpoint para registrar un gasto suelto (mercado,
entretenimiento, etc., como los del seed).

Efecto: POST /api/gastos/ sigue sin funcionar — antes por duplicar
PagosServicioFijoView con el serializer equivocado, ahora por un
KeyError con el serializer que sí correspondía a otra cosa.

FIX (reescribir GastosView.post() para que sea REALMENTE el registro de
un gasto puntual, dejando PagosServicioFijoView intacto para los pagos
de servicio):
    def post(self, request: Request) -> Response:
        e = GastoSerializer(data=request.data)
        e.is_valid(raise_exception=True)
        caso = RegistrarGastoUseCase(repositorio=DjangoGastoRepository())
        try:
            gasto = caso.ejecutar(
                usuario_id=request.user.id,
                categoria_id=e.validated_data["categoria_id"],
                prioridad_id=e.validated_data["prioridad_id"],
                monto=e.validated_data["monto"],
                fecha_gasto=e.validated_data["fecha_gasto"],
                periodo_mes=e.validated_data["periodo_mes"],
                periodo_anio=e.validated_data["periodo_anio"],
                estado=e.validated_data.get("estado", "Pagado"),
                descripcion=e.validated_data.get("descripcion"),
            )
        except (MontoInvalido, EstadoGastoInvalido) as ex:
            return Response({"detail": str(ex)}, status=status.HTTP_400_BAD_REQUEST)
        return Response(GastoSerializer(gasto).data, status=status.HTTP_201_CREATED)
(MontoInvalido y EstadoGastoInvalido ya están importados en este
archivo; no hace falta agregar nada más.)
