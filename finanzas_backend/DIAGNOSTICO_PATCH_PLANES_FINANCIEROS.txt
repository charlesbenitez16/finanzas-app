CAUSA #1 (la que te da el 500 ahora) — `activo` es read_only en el serializer
================================================================================
Archivo: modules/planes_financieros/interfaces/api/serializers.py

    class PlanFinancieroSerializer(serializers.Serializer):
        ...
        activo = serializers.BooleanField(read_only=True)

`read_only=True` le dice a DRF: "este campo lo pongo YO en la salida,
nunca lo acepto en la entrada". Entonces, aunque mandes `"activo": true`
en el body, `entrada.is_valid()` da True igual (no lo valida ni lo
rechaza), pero `entrada.validated_data` NUNCA va a tener la clave
"activo" — se descarta en silencio.

Reproduje exactamente tu body contra el serializer:

    validated_data: {'nombre': 'Plan Benitez Torres V1',
                      'porcentaje_gasto_fijo': Decimal('50.00'),
                      'porcentaje_ahorro': Decimal('33.00'),
                      'porcentaje_gasto_libre': Decimal('17.00'),
                      'fecha_inicio': datetime.date(2026, 9, 19)}
    'activo' in validated_data → False
    e.validated_data['activo'] → KeyError: 'activo'

Y tu views.py hace justo eso:

    def patch(self, request: Request) -> Response:
        e = PlanFinancieroSerializer(data=request.data); e.is_valid(raise_exception=True)
        caso = ActualizarPlanFinancieroUseCase(repositorio=DjangoPlanFinancieroRepository())
        try:
            plan = caso.ejecutar(
                ...
                activo=e.validated_data["activo"],    # <- KeyError acá
                ...
            )
        except PorcentajesNoSuman100 as ex:            # <- este except NO atrapa KeyError
            return Response(..., status=400)

El KeyError no está dentro de ningún try/except que lo espere (el único
except es para `PorcentajesNoSuman100`), así que sube sin manejar → DRF
lo convierte en 500. Esto pasa SIEMPRE, con cualquier body, mientras
`activo` siga marcado `read_only=True`.

QUÉ FALTA: en `PlanFinancieroSerializer`, sacarle `read_only=True` a
`activo` (o crear un serializer de entrada separado para este PATCH que
no lo tenga read_only). Mientras `activo` sea read_only, este endpoint
no puede funcionar.
